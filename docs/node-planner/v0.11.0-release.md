# NodeScope 0.11.0 tester build

Prepared from the local branch `feature/saved-plans-v3`: iOS 0.11.0 (1) and Android 0.11.0 (versionCode 28), version commit `817ee71`. Preparing these notes doesn't build, upload or publish anything.

0.10.6 wasn't released. Everything it contained (Estimated Coverage, Saved Plans, the iPad and Mac improvements and What's New; see [v0.10.6-release.md](v0.10.6-release.md)) ships in 0.11.0, together with Saved Plans v3:

- **A1, storage:** a new library format with separate result files, revisions, and safe migration from 0.10.x ([saved-plans-v3-a1.md](saved-plans-v3-a1.md)).
- **A2, named plans:** group studies into plans with notes; Update or Save as new; plans carried from Link Profile into Coverage ([saved-plans-v3-a2.md](saved-plans-v3-a2.md)). Candidate Sites can move into Saved Plans.
- **B, portable results:** saved results open on both platforms; Link Profile results are saved for the first time ([saved-plans-v3-b.md](saved-plans-v3-b.md)).
- **C, unsaved work:** recovery drafts survive switching analyzer, process death and crashes ([saved-plans-v3-c.md](saved-plans-v3-c.md)).
- **D, sharing:** export a study, plan or library to a `.nodescope` file and import copies ([saved-plans-v3-d.md](saved-plans-v3-d.md)).

## Before sending to testers

- **Device pass (not yet done).** Install over 0.10.6 or 0.10.5 with a real saved library and confirm everything is there; open a `.nodescope` file from AirDrop, Mail or a file manager; one iPhone ↔ Android round trip; switch analyzer with unsaved work and resume it.
- **Review of the import path.** Import reads files other people send, through a hand-written ZIP reader. It passes the 57 hostile shared cases. A code review of the D commits (November 16) found two bugs and eight smaller issues; all are fixed in the commit after `730be58`.

## Tell testers

Once this build saves Saved Plans, the library is in the new format. 0.10.x refuses to save over it (it doesn't delete it), so plans can't be edited after going back to an older version. Stay on the beta once installed. Exporting a library backup first is a good habit.

## What to test

Detailed checklists are in each deliverable's notes; these are the highlights.

- **Upgrade.** Update from 0.10.x with saved studies and candidate sites: everything is there, results open without calculating, and Settings → Cache & Storage → Saved Plans shows result storage.
- **What's New.** Updating from 0.10.5 shows it once; tapping Saved Plans, Estimated Coverage or Link Profile opens it; Settings → What's New reopens it. A fresh install doesn't show it.
- **Plans.** Create a plan with notes; add new and existing studies; move, rename, duplicate and delete studies; delete a plan (its studies become standalone). Save from Link Profile and Coverage with Update and Save as new.
- **Link Profile → Coverage.** Start Coverage from a Link Profile inside a plan: it's suggested for the same plan, nothing calculates until Calculate, and Back returns to the Link Profile.
- **Results.** A calculated Link Profile reopens with "Saved result · calculated …" and no terrain loading. Edit a height: the result clears until Calculate.
- **Unsaved work.** Edit a study without saving, switch analyzer and back: Saved Plans offers Continue unfinished study. Force-quit (iOS) or background with "Don't keep activities" (Android): the work comes back.
- **Sharing.** Back up the library and import it on the other platform; export a plan with notes off; import a study twice ("Name 2"); import a file that isn't from NodeScope (refused, nothing changes). The export preview's Analyzer line shows your analyzer for newly saved studies.
- **Estimated Coverage and Link Profile** as in 0.10.6: placing, calculating, tapping the map, large studies with Continue.
- **Layouts.** Light and dark, large text, portrait and landscape, iPad sidebars, Android tablets.

Coverage is a sampled estimate using assumed receiver equipment, not measured reception or a guarantee of connectivity.

## Known issues

- iOS Link Profile: after Calculate on a reopened study, the route sometimes stays dark until the map is moved or tapped. Present before A2; not fixed.
- Studies saved before this build have no recorded analyzer ("Unknown source") until their inputs are captured again.
- Neither platform can convert the other's 0.10.x coverage results; a library moved between platforms by a device transfer keeps those results only on the platform that made them.
- Android's Link Profile has no refraction or sample-count controls; an iOS study using them loses them if saved again on Android.
- Android's Import… picker shows every file; anything that isn't a NodeScope file is refused.

## App Store — What's New

New: Saved Plans. Group link profiles and coverage studies into named plans, with notes. Results are saved with them and open on iPhone, iPad and Android without calculating again, and a calculated Link Profile now reopens with its result.

Share and back up: export a study, a plan or your whole library as a file to send or keep, and open a NodeScope file to import a copy. Nothing in your library is replaced.

Unsaved work is kept when you switch analyzer or NodeScope closes; pick it up again from Saved Plans.

New: Estimated Coverage (Beta). Place a transmitter anywhere, on a known node, at your location or with a long press, and see where it's likely to be heard, based on terrain and your radio settings. Tap the map to check the predicted signal at any spot.

Better on iPad and Mac: sidebars start at the top of the panel, the map runs behind the live packets sidebar, and on the Mac ⌘1–⌘5 switch tabs, ⌘F searches and ⌘R refreshes.

After an update, NodeScope shows what's new. Reopen it anytime from Settings.

Coverage is an estimate from terrain data and the receiver you assume, not a guarantee of real-world reception.
